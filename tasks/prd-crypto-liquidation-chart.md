# PRD: 加密货币清算图表

## Status

- 状态：待办，尚未实施
- 优先范围：BTC、ETH 永续合约
- 目标数据源：Binance Futures、OKX
- 本文仅记录需求，不包含代码、配置或数据库变更

## Background

当前加密货币页面已经提供 Binance 和 OKX 的现货实时行情及 K 线，但不能观察合约市场的强制平仓情况。需要在数字资产详情页增加清算图表，帮助用户按时间、价格、方向和交易所查看多空清算规模及集中区域。

本文中的“清算”指交易所合约仓位被强制平仓，也常称为“爆仓”；“清算图表”包含实时清算柱状图和可选的价格区间热力图，不是交易或下单功能。

## Goals

- 接入 Binance Futures 和 OKX 的公开清算数据。
- 在 BTC、ETH 详情页展示实时多单、空单清算金额。
- 支持按交易所、时间范围、方向和计价单位筛选。
- 对实时事件进行服务端标准化、聚合和持久化，以支持刷新及跨浏览器恢复。
- 清楚标注数据延迟、连接状态、覆盖范围和估算口径。

## User Stories

### US-001: 实时清算事件

- [ ] 用户可以查看 BTC、ETH 最新清算事件。
- [ ] 每条事件显示交易所、合约、方向、清算价格、数量、折算金额和时间。
- [ ] 页面通过 SSE 或 WebSocket 增量更新，不需要整体轮询刷新。
- [ ] Binance 或 OKX 单个数据源断开时，另一数据源仍可继续展示，并显示连接状态。

### US-002: 清算时间图

- [ ] 以时间桶聚合清算金额，默认展示多单清算和空单清算的双向柱状图。
- [ ] 支持 `5m`、`15m`、`1h` 等聚合粒度，以及 `1h`、`4h`、`12h`、`24h` 时间范围。
- [ ] 鼠标悬停显示时间桶内总金额、事件数、最大单笔和交易所分布。
- [ ] 支持 Binance、OKX 和合并视图。

### US-003: 清算热力图

- [ ] 按时间和成交/清算价格区间聚合实际清算事件，展示清算集中区域。
- [ ] 热力图必须明确标注为“历史实际清算”，不得冒充基于订单簿推算的未来清算地图。
- [ ] 若后续接入第三方预测型清算热力图，必须作为独立数据类型和图层展示，并标明提供方及估算方法。

### US-004: 汇总指标

- [ ] 显示选定时间范围内的总清算金额、多单清算、空单清算、多空比例和最大单笔。
- [ ] 金额统一折算为 USDT/USD，同时保留原始合约数量。
- [ ] 合并多个交易所时按事件 ID 或稳定指纹去重，避免重复统计。

## Data Sources

### Binance Futures

- 优先评估 USD-M Futures 公开强平订单实时流，例如 `forceOrder` 类频道。
- 需要确认公共流的推送频率、是否聚合以及 BTCUSDT、ETHUSDT 永续合约字段口径。
- 如果官方接口不提供足够的历史回补能力，历史图必须依赖本服务从启用时开始持续采集，或另行配置第三方历史数据源。

### OKX

- 优先评估公共 WebSocket 的 `liquidation-orders` 类频道，覆盖 `SWAP` 合约。
- 需要确认订阅参数、速率限制、方向字段、破产价格和清算数量的含义。
- OKX 不可用或所在地区网络受限时，页面显示数据源降级，不应阻断 Binance 数据。

### Provider Rules

- [ ] 每个 Provider 实现独立适配器，统一输出标准清算事件。
- [ ] Provider URL 可配置，默认只允许受信任的 HTTPS/WSS 地址。
- [ ] 公共数据优先不使用 API Key；如第三方历史源需要 Key，只能通过环境变量或安全配置保存。
- [ ] 禁止在日志、接口响应或前端代码中暴露 API Key。

## Normalized Data Model

建议的标准事件字段：

- `id`：Provider 事件 ID；没有稳定 ID 时生成去重指纹。
- `exchange`：`binance` 或 `okx`。
- `symbol`：统一为 `BTC-USDT-SWAP`、`ETH-USDT-SWAP` 等规范代码。
- `side`：被清算仓位方向，统一为 `long` 或 `short`。
- `price`：清算或成交价格，并保留 Provider 原始字段来源。
- `quantity`：合约或标的数量。
- `notional`：统一计价后的清算金额。
- `currency`：金额计价币种。
- `occurred_at`：交易所事件时间。
- `received_at`：Gateway 接收时间，用于计算延迟。

聚合表至少保存 `symbol`、`exchange`、`bucket_start`、`interval`、`side`、`notional`、`event_count` 和 `largest_notional`。

## Suggested API Surface

以下接口仅作为后续设计输入：

- `GET /v1/crypto/liquidations/stream?symbols=BTC-USDT-SWAP,ETH-USDT-SWAP`
- `GET /v1/crypto/liquidations?symbol=BTC-USDT-SWAP&range=4h&exchange=all`
- `GET /v1/crypto/liquidations/buckets?symbol=BTC-USDT-SWAP&interval=5m&range=24h`
- `GET /v1/crypto/liquidations/heatmap?symbol=BTC-USDT-SWAP&price_bins=80&range=24h`

所有接口必须复用现有账号认证、请求限制和错误响应规范。

## UX Requirements

- [ ] BTC、ETH 详情页增加“清算”视图或标签页，不影响现有 K 线布局。
- [ ] 使用分段控件切换时间图和热力图，使用菜单筛选交易所和时间范围。
- [ ] 多单、空单使用语义稳定且色盲可辨的颜色，并配合文字或图例，不仅依赖颜色表达。
- [ ] 图表具备稳定高度和响应式宽度，在手机与桌面端不发生文字或图例重叠。
- [ ] 加载、部分数据源离线、无数据、错误和重新连接状态均有独立展示。
- [ ] 显示“最后更新”“数据延迟”和当前在线 Provider。
- [ ] 不在页面中暗示清算数据构成投资建议。

## Functional Requirements

- [ ] Gateway 启动独立的清算流订阅，不与现货 ticker 连接混用。
- [ ] 连接支持指数退避、心跳、断线重连和优雅停止。
- [ ] 事件写入数据库前完成字段校验、方向归一、金额换算和去重。
- [ ] 数据保留时间可配置，并提供聚合或清理机制控制数据库增长。
- [ ] 实时事件和历史查询使用相同的标准字段及方向语义。
- [ ] 前端重连使用游标或事件序号补齐缺口，不能重复累计清算金额。
- [ ] 服务重启后历史数据仍可查询；重启期间缺失的数据需明确标注，不能伪造回补。
- [ ] 所有查询限定允许的 symbol、时间范围和桶数量，防止高成本任意查询。

## Acceptance Scenarios

- [ ] 收到 Binance BTC 多单清算事件后，实时列表、时间桶和汇总金额只增加一次。
- [ ] 收到 OKX ETH 空单清算事件后，方向、数量和 USDT 金额转换正确。
- [ ] Binance 断开时 OKX 继续更新，页面明确显示 Binance 离线。
- [ ] 刷新页面后可以恢复最近 24 小时聚合数据，并继续接收实时事件。
- [ ] 切换 `5m` 到 `1h` 粒度后，各桶合计与同时间范围汇总值一致。
- [ ] SSE 重连和 Provider 重复推送不会导致同一事件重复统计。
- [ ] 移动端 BTC、ETH 清算图表、筛选器和图例不重叠。
- [ ] 没有历史回补来源时，页面明确显示数据采集起始时间。

## Non-Goals

- 不提供合约下单、平仓、杠杆设置或账户持仓管理。
- 不把现货成交量误当成合约清算量。
- 第一阶段不支持 BTC、ETH 之外的全部合约市场。
- 第一阶段不承诺提供未来价格的预测型清算地图。
- 不抓取未授权网页或绕过交易所访问限制。

## Open Questions

- 第一阶段只做实际清算时间图，还是同时实现价格热力图？建议先完成实际清算时间图。
- 历史数据只从启用时间开始积累，还是接入第三方回补 Provider？
- 原始事件保留多久，何时只保留聚合桶？
- 合并币本位和 USDT 本位合约时，金额换算采用事件价格还是同期指数价格？
- 清算方向在不同 Provider 字段中的映射需要通过官方样例和集成测试最终确认。
